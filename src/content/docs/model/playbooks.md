summary: "A playbook takes a project from its brief to its release, one stage at a time."
---

A playbook is the route a project follows. Each stage names what must exist before the project moves on, such as a brief, a charter or a test plan, and the work done in that stage.

Moving from one stage to the next is a **gate**, and a gate is a decision, so its tier says whether a person approves. The project drawn under Work runs on a playbook with four stages: brief, build, release and learn. Its release stage is a gate that a person approves, and its last stage keeps what the project learned.

Issues have stages of their own, inside the project's: build, review, verify and ship. An issue is not done when the code is written. It is done when it has been reviewed, verified and shipped.
